Executive Summary

The dashboard's Jenkins nightly pipeline deploys the latest upstream operators, then runs Cypress E2E tests. When an upstream operator fails to deploy (CrashLoopBackOff, DSC not ready, RBAC failure), the entire nightly is blocked and the failure is labeled cypress_found_bug. This report analyzes only upstream component bugs — dashboard product bugs, test infrastructure issues, and build/DevOps problems have been excluded.

Low-Hanging Fruit: 15+ bugs fixable with 10–25 lines of Go

Connection to AI Factory

RHOAIENG-87641, RHOAIENG-75513

The AI Factory initiative aims to enable many small PRs, parallel agents, and fast merge cycles. Upstream bugs that block the nightly are the #1 blocker to this model — each bug creates a 3–10 day feedback loop.

AI Factory GoalCurrent BlockerGap Analysis FindingProposed Solution
Fast merge cyclesNightly blocked ~1/3 of days by upstream bugs74% of blocking bugs are catchable at operator startup/envtestPush envtest recipes to upstream repos
Many small PRsCI queue backs up when nightly is broken82/111 E2E tests fail on upstream issues, not dashboard bugsSeparate deployment validation from UI testing
Reliable signalcypress_found_bug label mixes upstream, test-infra, and product bugs68% upstream, 16% test infra, 8% product, 8% buildSplit into distinct labels

Proposed AI Factory Workstreams

1. Upstream envtest recipe generator (AI-powered, OpenAI-compatible)

An AI-powered skill (OpenAI-compatible) that analyzes an upstream repo, identifies missing envtest coverage, and generates Go test recipes (non-admin RBAC, finalizer ordering, bootstrap). This is the highest-leverage automation: 15+ bugs × ~15 lines each = a skill that can generate fixes at scale.

2. cypress_found_bug triage skill (AI-powered, OpenAI-compatible)

An AI-powered skill (OpenAI-compatible) that takes a new cypress_found_bug issue, classifies it (upstream/test-infra/product/build), identifies the root component, checks if the upstream repo has a test that should have caught it, and suggests the fix. This replaces the 15–60 min manual triage step.

3. E2E → backend test parity tracker

A periodic report (or skill) that maps Cypress E2E tests to upstream backend tests and flags gaps. The parity table in this document is the v1 of this.
